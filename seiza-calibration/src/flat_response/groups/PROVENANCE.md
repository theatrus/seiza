# Shared flat grouping policy

`model.rs`, `lights.rs`, `overrides.rs` and `rows.rs` were extracted from
[PSF Guard](https://github.com/theatrus/psf-guard/tree/79f5e31d53b8371e8fcd0b22a9b69692412cd8b4/src/calibration/flat_groups/measure),
commit `79f5e31d53b8371e8fcd0b22a9b69692412cd8b4`, copyright the PSF Guard
contributors, under Apache-2.0 (the same license as Seiza). Their numerical
rules, event/evidence keys, thresholds, and 48 unit tests are retained.

Adaptations: imports now name this crate's existing response/dust kernels;
catalog-only test imports now name the equivalent shared records; records
crossing the batch boundary gain serde derives and reject unknown fields.
`mod.rs` adds request validation and assembles batch results for bindings.
The pure native `Book` API remains available for the PSF Guard migration.
No catalog, SQLite, file-loading, or cache side effects moved with it.

The integration fixture comes from seiza-mac PR #92, commit
`d574764e6713f7ab3c0826452991504d6c6f6ca3`,
`Tests/Fixtures/CalibrationParity/psf-guard.json`, `flatGroups`. Its capture
harness ran the actual PSF Guard library at the commit above, using
seiza-calibration 0.8.1 and seiza-stacking 0.51.2. The committed request
reconstructs the harness inputs; the expected families, boundaries, events,
and placements are that captured output, with field names changed from
camelCase to snake_case. Expected values were not generated by this port.

This extraction does not claim full calibration-library parity: peer grading
orchestration, quality eligibility, temporal dark/cohort selection, complete
master recipes, and session-aware expanded planning remain separate work.
