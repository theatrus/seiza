# Seiza 0.47.0

Seiza 0.47.0 makes the calibration library a first-class Rust API that PSF
Guard calls as its own code and Python binds directly, describes the C ABI's
calibration calls with a JSON Schema, and adds completed-stack reports with
diagnostic charts and native OSC and RGB project analysis.

## The calibration library is a native API

PSF Guard's calibration code (frame selection, grading, settings, master
decisions, flat retries and the flat grouping job's planning) is now Seiza's
native Rust API, moved rather than reimplemented. PSF Guard calls it where it
always called its own code, with no requests or JSON in between. Masters,
grades, flat groups and stacks keep their keys, so nothing rebuilds.

- **Settings are typed:** `rules::SettingKey` names every setting.
  `RuleBook::validated` checks layers the way a settings panel saves them,
  while `RuleBook::new` still lets a value a newer build wrote fall through.
- **The decisions are native:** a `QualityIndex` regrades and decides
  kept-out reasons, a `Library` selects for each light, and
  `resolve_session` resolves a selection into its `Session`, which takes
  build failures, flat use and pedestal fits. `FlatRetry` decides a flat
  master's retries one step at a time: leave a drifting minority out, else
  take the next session, else keep the first set with a note.
  `FlatRetry::for_session` keeps the session's policy, so a supplied set
  never takes another session.
- **Flat grouping places lights natively:** a book built from stored rows
  (`groups::prepare`) says where each light stands (`Book::place_light`).
- **Every host gets the same checks:** frames, lights, night shifts and
  grouping limits are refused natively, as the C ABI refused them.

Python binds the same API as classes: `CalibrationRules`,
`CalibrationQuality`, `CalibrationLibrary`, `CalibrationSelection`,
`CalibrationSession`, `FlatRetry` and `FlatGroups`, plus the flat-work stages
and the decision functions a host that builds its own masters makes. seiza-py
converts values to and from the core's types directly, with no JSON text.

See [calibration-library.md](../calibration-library.md)
([#403](https://github.com/theatrus/seiza/pull/403)).

## A schema for the C ABI's calibration calls

The C ABI keeps running each calibration workflow as one JSON call, so the
apps need few exports. Those calls now live in `library::json`, behind a
`json` feature only seiza-cabi enables. `seiza_calibration_library_schema_json`
returns a draft 2020-12 JSON Schema of every calibration, flat-group and
flat-stability call's request and answer, in camelCase as C sends them.
`seiza-cabi/include/seiza_calibration_library.schema.json` is the same
document, for app builds to generate their types from.

## Completed-stack reports

Completed stacks can write HTML and JSON reports of their support, sample
rejection and admitted inputs, for one stack or a named collection such as an
SHO session (`seiza stack --report-html`, `seiza stack-report`). Cheap
reports chart admission and final rejection from retained measurements, with
no pixels read again. Rich reports add a source-analysis pass for star
shape, noise and sampled integration depth
([#399](https://github.com/theatrus/seiza/pull/399),
[#402](https://github.com/theatrus/seiza/pull/402)).

## OSC and RGB project analysis

Project analysis now measures one-shot-color and RGB inputs. A Bayer mosaic is
split into its four native lattices and RGB into its three planes, with no
demosaicing or white balance, and star sizes are given in original-image
pixels. Report schema 3 keeps one record per source and component
([#404](https://github.com/theatrus/seiza/pull/404)).

## Changes for hosts

- **Rust:** the request-style calls (`evaluate`, `plan_masters`,
  `master_cohort`, `flat_retry`, `plan_flat_responses`, `plan_flat_work`,
  `finish_flat_work`, and the grouping plan that was `groups::evaluate`)
  moved to `library::json` behind the `json` feature. Several native names
  changed; see [#403](https://github.com/theatrus/seiza/pull/403).
- **Python:** `calibration_library_plan`, `calibration_master_plan`,
  `calibration_master_cohort`, `calibration_flat_retry` and `flat_group_plan`
  give way to the native classes. `master_flat_stability` takes keywords
  only. The record types `CalibrationSession` and `CalibrationQuality` are
  now `CalibrationSessionRecord` and `CalibrationQualityRecord`. An `f32`
  reaches Python at its exact value, as C's JSON gives it.
- **C:** the calibration calls and their answers keep their shapes. A quality
  record's `grade` must be `ok`, `suspect` or `poor`. Calibration session
  policy is version 5: lights whose masters take the same frames share one
  session.
- **Session-plan contexts:** a context saved by 0.46 reopens, and reports a
  new configuration fingerprint once, because the fingerprint no longer
  includes the file identity that broke on remounted disks.

## Package and output versions

The workspace packages (`seiza`, `seiza-cabi`, `seiza-cli`) and the Python
package are 0.47.0. `seiza-calibration` is 0.11.0, `seiza-stacking` is 0.54.0
and `seiza-analysis` is 0.2.0. `seiza-parallax` 0.19.5 carries the compatible
Seiza dependency; its behavior is unchanged.

Stacking output stays 0.51.0 and stretch output stays 0.3.0. Existing numerical
summaries are unchanged; hosts keep their existing output-version cache keys.
