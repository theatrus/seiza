# Seiza 0.51.0

Seiza 0.51.0 registers frames through a quadratic warp by default, so stacks
of a sinking target keep their colours together at the corners. Learned noise
models now keep an image's holes and read drizzled noise at its true level, and
a new crate reads SER planetary sequences.

Stacks made with default options change, so `seiza_stacking::OUTPUT_VERSION`
moves to 0.59.0; see [Output versions](#output-versions).

## A quadratic warp by default

[#470](https://github.com/theatrus/seiza/pull/470)

Differential refraction squeezes each frame along the altitude direction, more
as the target sinks. A similarity (shift, rotation, uniform scale) cannot follow
it, so filters shot in turn kept different leftover stretches. On a 3.9° field
the quadratic warp brings blue to green from 0.59 px RMS to 0.03 px.

- `RegistrationOptions::default()` is `RegistrationModel::Quadratic`, as the CLI
  already was. A frame with too few paired stars keeps its similarity.
- Python's `StackOptions(registration_model=...)` defaults to `"quadratic"`.
- Saved options keep their bytes and meaning: options read without a model are
  still a similarity. A C ABI `"registration"` object that gives no model is a
  similarity; leave the whole object out to get the default.
- `seiza color` resamples channels through the similarity alone, as before, and
  now says so.

## Learned noise models: holes and spread noise

[#462](https://github.com/theatrus/seiza/pull/462),
[#463](https://github.com/theatrus/seiza/pull/463)

- **Hole guard.** A stack can hold pixels far below its sky in every frame,
  such as hot pixels a dark took too much from. Every model filled them and
  overshot into bright spikes. A card's `reading.holes` masks them, fills them
  from the median of their neighbours before the network runs, and puts them
  back after. On one Hα night the largest change inside the holes fell from
  2,463σ to 8σ (plain) and from 6,858σ to 15σ (drizzled).
- **Spread noise.** A drizzled stack spreads each pixel's noise over its
  neighbours, so it reads less noise than it holds. A card's
  `reading.noise_correlation` gives the level the model was trained at, and the
  image's noise map rises by the image's excess over it.
- **Cache keys.** A report's `sha256` covers the graph alone, but a card's
  settings change the output too. `ModelBundle::card_sha256` covers the card;
  C reports and listings carry `cardSha256`, Python `card_sha256`, and the
  CLI's FITS header `MDCARD`. Hosts that keyed cached results on `sha256`
  should key them on `card_sha256`.
- The guard's settings appear in C (`holes`), in Python (`HoleGuard`, on
  `DenoiseReport.holes` and `InstalledModel.holes`) and in the CLI's FITS header
  (`MDHOLES`). A card that lacks both settings runs as before.
- The training harness, corpus passes and design record live under `training/`
  and [docs/design/ml-restoration-training.md](../design/ml-restoration-training.md).

## SER sequences

[#464](https://github.com/theatrus/seiza/pull/464)

The new [`seiza-image-ser`](../../seiza-image-ser/README.md) crate reads raw SER
planetary captures, Siril's included, a frame at a time: every bit depth and
colour layout, per-frame timestamps, and files past 4 GiB. It is a Rust crate
only for now, with no link to image dispatch, stacking, the CLI, C or Python.

## Output versions

- Stacking: 0.59.0. Stacks with default options and enough stars for the fit
  change. A new case stacks a 200-star field squeezed by refraction under both
  models.
- Stretch (0.3.0) and pipeline (0.1.0): unchanged.

## Breaking changes

- `seiza-stacking` 0.59.0: `RegistrationOptions::default()` is now quadratic.
- `seiza-model` 0.2.0: new card settings and report fields
  (`holes`, `noise_correlation`, `card_sha256`); a card that asks for a setting
  this build does not know is refused.
- `seiza-pipeline` 0.3.0, `seiza-analysis` 0.6.0 and `seiza-parallax` 0.21.0
  move with `seiza-stacking` and `seiza`, whose types they use.
