# Seiza 0.54.0

Forced aperture photometry measures a target and its comparison stars at
positions you supply, on one linear mono plane: a mono sub, or the green
plane of a colour one. It needs no star detection, reference image or
continuum fit, so it suits time series such as variable stars and
exoplanet transits. Each position gets a signed flux and its error, a
magnitude where the flux is positive, the local sky and its noise, and
flags for saturation, missing coverage and an annulus too sparse to trust.
Apertures weight each pixel by its exact overlap with the circle. A mask,
a saturation map and a per-pixel uncertainty map are optional. Rust calls
`seiza_stacking::aperture_photometry`, the C ABI
`seiza_aperture_photometry_json`, and Python `seiza.aperture_photometry`
(see `seiza-py/examples/aperture_photometry.py`). Aperture sums, areas and
errors match photutils on synthetic data; the feature has not yet been
tried on real subs.

Reintegrating an expanded mosaic can now level the panels' backgrounds
through their overlaps: `--reintegrate --match-mosaic-backgrounds` in the
CLI, `match_mosaic_backgrounds` in Rust and Python, and
`matchMosaicBackgrounds` in the C ABI's stack options. It fits one additive
plane per panel and is off by default. Use it on calibrated panels with
matching gains; vignetting left in by a missing flat can pass for a sky
gradient. On real data it helped some mosaics and hurt others, as
[the validation report](../design/mosaic-background-validation.md) shows.

Registered-frame mosaics that ask for panel matching (`mosaic_panels`) no
longer fit a shared vignetting bowl. Overlaps cannot tell that bowl from a
real sky gradient, so it absorbed valid corrections and tied unconnected
panels together. Their output changes, so `seiza_stacking::OUTPUT_VERSION`
moves to 0.62.0, and hosts that key cached stacks on it will rebuild them.
Stacks that do not match mosaic panels come out as before.

Stretch, pipeline and model output versions stay the same.
