# Seiza 0.44.1

Seiza 0.44.1 fixes local normalization on an expanded canvas, contributed
by @ppicazo (#375).

## Expanded canvases refuse local normalization

`seiza stack --reference expand --normalization local` planned the whole
mosaic, rejected every frame with "too few overlapping finite pixels for
normalization", and then failed with "no light frames were accepted against
the reference image". Local normalization fits each tile of a frame against
the canvas beneath it, and a frame joining a growing canvas has tiles with
no canvas beneath them.

An expanded canvas now refuses local normalization before planning reads a
frame, as it refuses Bayer drizzle:

```text
an expanded canvas does not support local normalization, whose tiles each need canvas beneath them; use local-background or global
```

The CLI, the C ABI and Python all reach the check through
`LiveStacker::with_expanding_reference`. On the 129-frame Seestar mosaic, the
CLI now stops with the reason after its reference choice, 12 s in, instead of
after planning. None, global and local-background normalization are
accepted as before. What local normalization should mean on a mosaic is left
open in #365.

## Package and output versions

The workspace packages (`seiza`, `seiza-cabi`, `seiza-cli`) and the Python
package are 0.44.1, and `seiza-stacking` is 0.51.1. Stacking output stays
0.51.0 and stretch output 0.3.0, so cached stacks remain valid.
