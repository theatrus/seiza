# Seiza 0.48.2

Seiza 0.48.2 lets `seiza stack` accept flats whose rotator angle is a
placeholder, and makes masters from `seiza master` carry `IMAGETYP` so other
software files them as calibration frames. It also fixes atomic writes to
network shares from a Mac, and adds reintegration of a chosen subset of a
stack's frames.

## Flats with a placeholder rotator angle

N.I.N.A. records a rotator angle of 0 for flats taken without a rotator
reading. Lights from a manual rotator record their real angle, so
`seiza stack --flat` refused every flat for its rotation
([#391](https://github.com/theatrus/seiza/issues/391)).

- **`seiza stack --light-rotation recorded|unknown|DEGREES`** sets
  `MatchTolerances::light_rotation` from the command line.
  - `recorded`, the default, compares each light at the angle it recorded.
  - `unknown` skips the angle check, so a flat at any angle is accepted. Use
    it only when the flats or the lights recorded a placeholder.
  - `DEGREES` compares every light at one angle you measured, such as a
    plate-solved position angle. A negative angle works without `=`.
  - The option applies to `--flat` and to the flats of `--joint-canvas`
    groups. `--allow-flat-gain-offset-mismatch` now also works with only
    `--joint-canvas`.
- When the lights were compared at their recorded angles and a flat is
  refused for its angle alone, `seiza stack` suggests both options.
- **`Error::FlatRotation`** is the stacking error for a flat that passes
  every optics check except its rotator angle, so a host can offer its own
  setting without reading the message. Its text is the calibration error it
  was before. The C ABI, Python and a live stack's frame rejection treat it
  as a calibration error.
- `LightRotation` implements `FromStr` and `Display` (`recorded`,
  `unknown`, or an angle). Python's `MatchTolerances(light_rotation=...)`
  parses its string form with them, so `"90"` is accepted as well as `90`.
- The stack report records `calibration.light_rotation` and
  `calibration.allow_flat_gain_offset_mismatch` when they are set
  ([#416](https://github.com/theatrus/seiza/pull/416)).

## Masters declare their kind in `IMAGETYP`

A master from `seiza master` recorded its kind only in `SEIZAMST`. Software
that sorts frames by `IMAGETYP` took it for a light: PSF Guard imported a
folder of Seiza masters as lights with no target
([#394](https://github.com/theatrus/seiza/issues/394)). Masters now also
write `IMAGETYP` as `MASTER BIAS`, `MASTER DARK` or `MASTER FLAT`. A master
integrated from flat-darks is a `MASTER DARK`, which is how Seiza reads it
and what PixInsight recognizes. Seiza still reads the kind from `SEIZAMST`
first, so it reads its masters as before. Masters already written keep only
`SEIZAMST`; PSF Guard reads the kind from there
([#415](https://github.com/theatrus/seiza/pull/415)).

## Reintegrating chosen frames

- `LiveStacker::reintegrate_frames` integrates only the admitted frames a
  caller names, on the stack's grid and with its normalization reference
  and weights. Stacks of disjoint subsets share their grid and
  normalization exactly. A path that names no admitted frame is refused as
  `Error::NotAdmitted`; an empty list or a frame named twice is refused.
- C: `seiza_live_stacker_reintegrate_frames`. Python:
  `LiveStacker.reintegrate(frames=...)`.
- Python's `StackOptions` takes `interpolation` (`"bilinear"` or
  `"lanczos3"`), which the C ABI's stack options already carry.
- Python's `rc_astro_process_image` runs an RC-Astro tool on an image in
  memory and returns the result in the image's own units, as the C ABI's
  file call does.
- A new `training/` package, outside the published crates, builds training
  data for the learned restoration models from a telescope corpus and from
  PSF Guard's finished stacks
  ([#414](https://github.com/theatrus/seiza/pull/414),
  [#417](https://github.com/theatrus/seiza/pull/417)).

## Fixes

- Atomic writes to an SMB share from a Mac succeed. macOS asks for a full
  sync (`F_FULLFSYNC`), which an SMB share refuses, so every FITS, XISF and
  PNG write, calibration library cache file, saved stack context, and the
  CLI's stack page, analysis, stack report and provenance failed there with
  `Operation not supported (os error 45)`. `seiza_fits::sync_file` falls
  back to a plain `fsync` when the file system refuses the full sync, and
  each of those writes syncs through it
  ([#418](https://github.com/theatrus/seiza/pull/418)).

## Package and output versions

The workspace packages (`seiza`, `seiza-cabi`, `seiza-cli`) and the Python
package are 0.48.2. Each other crate that changed takes a patch release, since
its changes only add to its API:

| Crate | Version |
|---|---|
| `seiza-calibration` | 0.12.1 |
| `seiza-stacking` | 0.56.1 |
| `seiza-fits` | 0.7.1 |
| `seiza-xisf` | 0.8.1 |
| `seiza-image-io` | 0.12.1 |

Stacking output stays 0.51.0 and stretch output stays 0.3.0. Existing
numerical summaries are unchanged; hosts keep their existing output-version
cache keys.
