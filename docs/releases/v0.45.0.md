# Seiza 0.45.0

Seiza 0.45.0 prepares several mosaic frames at once within a memory budget
([#382](https://github.com/theatrus/seiza/pull/382)). It also makes the CLI
normalize an expanded canvas globally by default
([#380](https://github.com/theatrus/seiza/pull/380)), and lets flats taken at a
different gain or offset calibrate lights when the caller allows it
([#381](https://github.com/theatrus/seiza/pull/381)).

## Mosaic frames sized by their footprints

A frame joining an expanded canvas is resampled onto only the part of the
canvas it covers, but each frame in preparation was costed at the whole canvas.
On a four-panel mosaic of 88 megapixels from 26-megapixel frames, each worker
reserved 6.5 GiB for frames that need 2.4 GiB, so a host's budget ran a large
canvas one frame at a time.

`LiveStacker::pipeline_memory` gives the estimate every pipeline now plans
with. It costs a mosaic frame at the largest frame planning read, at any
rotation and the largest scale the acceptance criteria admit, with each side
held to the canvas's. A reopened context takes its largest panel instead.
`push_fits_pipelined_with_pool` fits its workers to the budget by it, and
`push_fits_pipelined` derives its worker count from it, so apps using the C ABI
prepare several mosaic frames at once too. Hosts read it through
`seiza_live_stacker_pipeline_memory_json` or Python's
`LiveStacker.pipeline_memory` instead of copying Seiza's geometry. Ordinary
stacks keep their reference-sized estimate.

## Global normalization for CLI mosaics

`seiza stack --reference expand` now defaults `--normalization` to `global`;
other stacks keep `local-background`. On a Seestar M31 mosaic, global
normalization left a smaller sky gradient and fewer lumps, at about 0.7% more
noise. For mosaics whose panels come from different nights, pass
`--normalization local-background`. An explicit `--normalization` always wins.
The library, C ABI and Python already defaulted to global.

## Flats at another gain or offset

`MatchTolerances::allow_flat_gain_offset_mismatch`, off by default, lets a flat
taken at a different gain or offset calibrate lights. It also allows applying a
master flat that records dark subtraction. Dark and light, flat and flat-dark,
and readout-mode matching stay strict. The C ABI and Python carry it, and saved
contexts and replays keep it. `MatchTolerances` gains a public field, so code
building it from a struct literal must add the field or use
`..Default::default()`.

Hinted image solves open the blind index only when header and hinted solving
fail. Rejection messages keep enough precision that a fraction just below its
limit no longer reads as equal to it.

## Package and output versions

The workspace packages (`seiza`, `seiza-cabi`, `seiza-cli`) and Python package
are 0.45.0. `seiza-stacking` is 0.52.0 and `seiza-calibration` is 0.9.0.
`seiza-parallax` 0.19.3 carries the compatible Seiza dependency; its behavior
is unchanged. Stacking output stays 0.51.0 and stretch output stays 0.3.0, so
cached stacks and previews remain valid.
