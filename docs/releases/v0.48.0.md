# Seiza 0.48.0

Seiza 0.48.0 reads a window of an image's samples without decoding the rest,
so a viewer can show the value under its pointer over a stack of gigabytes,
and reads FITS and XISF headers through `seiza-image-io`, with an XISF frame's
PixInsight plate solution included.

## Windowed reads

A windowed read takes only the window's rows from a mapped file. A tile-
compressed FITS image decodes only the tiles that cross the window. A
64 × 64 read from a 40000 × 40000 float image allocates under 512 KB.

- **`seiza_fits::read_window`** reads the HDU `FitsImage::open` reads, at
  any BITPIX. Its samples are bit for bit what
  `FitsImage::open(...).into_physical_f32()` gives at those pixels: BZERO,
  BSCALE and BLANK applied, and 64-bit unsigned samples kept unsigned.
- **`seiza_xisf::read_window`** reads the first image from an attached,
  external, inline or embedded block, in planar or normal storage. Its
  `XisfWindow` can put a normalized `0:1` image on a chosen scale by
  `XisfImage`'s rules. Compressed, CIELab and complex images are refused.
- **`seiza_image_io::read_window`** chooses the container as `read_astronomy`
  does. Its `normalized_full_scale` works as stacking's: `Some(65535.0)` puts
  a `0:1` XISF image on a 16-bit camera's scale, and `None` leaves samples as
  stored.
- **`ImageWindow`** carries the image's size and plane count and the request
  clipped to the image. A side longer than `MAX_WINDOW_EDGE` (1024) is
  refused.

The C ABI fills a caller-owned buffer with `seiza_read_image_window`, where
a scale of 0 leaves samples as stored. Python's
`read_image_window(path, x, y, width, height, *, normalized_full_scale=None)`
returns a `float32` array shaped `(planes, height, width)`
([#407](https://github.com/theatrus/seiza/pull/407)).

## Header reads

- **`seiza_image_io::read_header(path)`** reads a header without decoding
  pixels. It returns the cards `read_astronomy` gives the image, a FITS
  file's `HISTORY` and `COMMENT` text, and, for an XISF file without WCS
  cards, its PixInsight `AstrometricSolution` as WCS cards. A frame solved in
  PixInsight therefore reads as solved.
- **`read_header_as(path, format)`** reads a file whose name does not say its
  container, such as an upload under a temporary name.
- **`Format::astronomy(path)`** is the container choice `read_astronomy`,
  `read_window` and `read_header` share. `read_solve_prior` and
  `read_capture_time` use it too.
- **`AstronomyImage::rescale_normalized_to(full_scale)`** puts a whole `0:1`
  XISF image on a chosen scale. It and `XisfImage`'s methods share one rule,
  `seiza_xisf::rescale_normalized`.

The C ABI returns a header as `seiza_read_image_header_json`, with
`headers`, `history` and `comments`. Python's `read_image_header(path)`
returns the same dict ([#408](https://github.com/theatrus/seiza/pull/408)).

## Package and output versions

The workspace packages (`seiza`, `seiza-cabi`, `seiza-cli`) and the Python
package are 0.48.0. `seiza-fits` is 0.7.0, `seiza-xisf` is 0.8.0 and
`seiza-image-io` is 0.12.0. `seiza-stacking` 0.55.0 and `seiza-analysis`
0.3.0 carry the new dependencies, which their public types expose; their
behavior is unchanged. `seiza-parallax` 0.19.6 carries the compatible
dependencies only.

Stacking output stays 0.51.0 and stretch output stays 0.3.0. Existing
numerical summaries are unchanged; hosts keep their existing output-version
cache keys.
