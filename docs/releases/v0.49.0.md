# Seiza 0.49.0

Seiza 0.49.0 measures stars the way N.I.N.A. and Hocus Focus do, so a host
can compare its own measurements with the ones they recorded. It also adds
distributed stacking's first phase, PixInsight's MLDenoise as an external
tool, and resampling by a stacked frame's registration alone.

Several crates take a minor version because their APIs changed; see
[Breaking changes](#breaking-changes).

## Star measurements that match N.I.N.A. and Hocus Focus

[#426](https://github.com/theatrus/seiza/pull/426)

- **N.I.N.A.'s built-in detector follows N.I.N.A.'s own source.** The
  detector now runs step-by-step ports of the Accord.NET filters N.I.N.A.
  uses:
  - bicubic resize;
  - integer Gaussian blur and Canny;
  - SIS threshold;
  - 3×3 dilation;
  - an 8-connected blob counter with edge points and its circle check.

  It used Otsu, another resize and a contour detector. A C# harness built
  from N.I.N.A. 3.1.2 and Accord's sources gives the same star counts and
  HFR as the port on real frames.
- **`StarDetectionParams::default()` is High sensitivity with no noise
  reduction**, N.I.N.A.'s default since 3.0. Set `image_scale_arcsec`
  (206.265 × pixel size in µm ÷ focal length in mm) so High shrinks the
  frame as N.I.N.A. does.
- **`StarDetectionParams.measurement`** picks the measurement of N.I.N.A.
  3.1, 3.2 (the default) or 3.3. The 3.3 measurement takes HFR from a
  centroid-refined curve of growth and fills `DetectedStar.fwhm` and
  `eccentricity`.
- **Hocus Focus 4.** `HocusFocusParams.version` picks the v3 measurement,
  the default, or v4. Use `HocusFocusParams::v4()` for v4's defaults. v4
  ports Hocus Focus 4.0.0.21's detector: its structure stage, adaptive
  binarization, a local background plane per star, a contamination gate,
  and HFR over a circular aperture. On one validation rig it matches the
  star counts and HFR Hocus Focus recorded frame by frame.
- The v3 measurement now works on the hot-pixel-filtered image, centres
  each star by brightness, and reports the frame's HFR as the median, as
  Hocus Focus does.
- **N.I.N.A.'s autofocus crop and brightest-stars setting**
  ([#428](https://github.com/theatrus/seiza/pull/428)). N.I.N.A. applies the
  profile's autofocus crop ratios and its "use brightest n stars" count
  to the measurement of every frame, not only to autofocus. Hocus Focus
  keeps them unless its "Use AutoFocus Crop" option is off.
  `HocusFocusParams.autofocus_inner_crop_ratio`, `autofocus_outer_crop_ratio`
  (1 = off) and `autofocus_brightest_stars` (0 = all) reproduce this. Given
  each rig's own profile settings, Hocus Focus 4 frames from three rigs now
  match the star count and HFR N.I.N.A. recorded, frame by frame.

Not yet matched: HFR from N.I.N.A.'s built-in detector at High sensitivity
reads about 12% low on one rig, and a faithful v3 detection stage is still
to come.

## Distributed stacking, phase 1

[#413](https://github.com/theatrus/seiza/pull/413)

A channel can be stacked as partial stacks, one per session, on one
reference grid. The partial stacks combine into what one stack of every
light gives, apart from rejection, which runs within each session. Every
file describes itself, so a run resumes by key. The new `seiza-pipeline`
crate holds this. `seiza-image-io::save_images` writes several images to
one FITS or XISF file; `read_astronomy_named` and `read_named_header` read
one back. `StackSnapshot::weight_sum` keeps the sum of weights of a weighted
stack.

## PixInsight's MLDenoise and RC-Astro

[#420](https://github.com/theatrus/seiza/pull/420),
[#422](https://github.com/theatrus/seiza/pull/422),
[#423](https://github.com/theatrus/seiza/pull/423)

- Seiza runs PixInsight's MLDenoise through an installed PixInsight, from
  Rust, C and Python.
- RC-Astro's tools now get images on the same scale MLDenoise uses, and
  uncovered (NaN) samples stay uncovered. Before, one NaN could make
  NoiseXTerminator return the whole image as NaN.
- `split_stars` keeps its result on the image's own scale.
- `EXTERNAL_EXCHANGE_VERSION` is available to C and Python, so a host can
  key caches on the mapping.

## Resampling by a frame's registration

[#421](https://github.com/theatrus/seiza/pull/421)

`RegisteredFrameMapping::resample_geometry` resamples another image of a
frame's size, such as its dark or a mask, onto the stack's grid without the
frame's normalization. C: `seiza_frame_mapping_resample`.

## Breaking changes

- `seiza-stars` 0.5.0: `StarDetectionParams`, `DetectedStar` and
  `HocusFocusParams` have new fields, and the default sensitivity is High.
  Build them with `..Default::default()`.
- `seiza-stacking` 0.57.0: `StackSnapshot` has a new `weight_sum` field.
- `seiza-fits` 0.8.0: `FitsError` has a new `ImageNotFound` variant.
- `seiza-xisf` 0.9.0, `seiza-image-io` 0.13.0, `seiza-analysis` 0.5.0,
  `seiza-parallax` 0.20.0 and `seiza-pipeline` 0.2.0 move with the crates
  above, whose types they use.

Output versions are unchanged: stacking 0.51.0 and stretch 0.3.0.
