# Seiza 0.46.0

Seiza 0.46.0 adds shared calibration-library policy, session-aware mosaic
calibration, reusable canvases across filters, and standalone project analysis.
The Rust core, C ABI and Python package expose the same processing machinery.

## Calibration policy shared with PSF Guard

The calibration library now owns PSF Guard's measured flat grouping, grading,
candidate selection, master adoption and dependency planning. Hosts supply
metadata, cached measurements, stored grades and manual choices; planning does
not reopen images or require a Seiza-owned database. Immutable prepared groups
can be reused across selections. Hosts retain file verification, caches,
master execution and persistence.

The shared settings schema exposes 43 controls, including rig overrides,
coherence rules and external-master preferences. Flat stability measurement
and the retry state machine preserve the original trim, alternate-session and
warning decisions, with options to change retry policy. Returned sessions can
be passed directly back into retry planning. File and cached-image measurement
APIs use the same numerical implementation. Invalid settings are rejected with
their setting and layer identified. See [calibration-library.md](../calibration-library.md)
and [flat-groups.md](../flat-groups.md) ([#385](https://github.com/theatrus/seiza/pull/385)).

Expanded mosaics accept immutable per-light calibration sessions. Planning,
integration, checkpoints and reintegration use each light's assigned masters,
matching gates, scaling and fitted pedestal, including interleaved A/B/A
sessions. Existing contexts keep their behavior; older readers refuse contexts
carrying the new session metadata. See
[calibration-sessions.md](../calibration-sessions.md).

## One mosaic grid across filters

Reuse an expanded canvas for independent Ha/OIII/SII stacks, or jointly plan
the union of explicit filter groups before integrating each group separately.
Outputs share dimensions, geometry and WCS where available. Each filter uses
its own calibration and normalization reference; unobserved areas remain NaN.
Disconnected fields still require stellar overlap to join the canvas.

The CLI adds `--reference-canvas`, `--joint-canvas` and `--save-canvas`.
Rust, C and Python offer the same operations, including reuse of saved
session-calibrated canvases. Filter groups are explicit; automatic splitting
and SHO compositing remain host operations
([#392](https://github.com/theatrus/seiza/pull/392)).

## Project quality and depth reports

`seiza analyze` measures project quality and sampled integration-depth trends
without producing a full stack. The new `seiza-analysis` crate, C ABI and Python
expose the engine and self-contained JSON/HTML reports. Metrics-only mode skips
registration and depth estimation. The initial scope is monochrome, non-Bayer
FITS/XISF, with comparisons within one pointing and filter.

Reports include stellar shape and SNR, noise/background measurements,
registration diagnostics, processing outcomes and descriptive depth trends.
These are diagnostics; advisory warnings do not automatically reject frames,
and depth estimates do not reproduce production calibration, weighting or
rejection. The HTML report adds searchable frame details, keyboard controls,
dark mode and complete JSON download. See the
[analysis documentation](../../seiza-analysis/README.md)
([#384](https://github.com/theatrus/seiza/pull/384),
[#393](https://github.com/theatrus/seiza/pull/393)).

The CLI also carries the flat gain/offset allowance through both reference
setup and integration. GitHub Actions and Rust/Python lockfile dependencies
are updated.

## Package and output versions

The workspace packages (`seiza`, `seiza-cabi`, `seiza-cli`) and Python package
are 0.46.0. `seiza-calibration` is 0.10.0, `seiza-stacking` is 0.53.0, and the
new `seiza-analysis` crate is 0.1.1. `seiza-parallax` 0.19.4 carries the compatible
Seiza dependency; its behavior is unchanged.

Stacking output stays 0.51.0 and stretch output stays 0.3.0. Existing numerical
summaries are unchanged; hosts keep their existing output-version cache keys.
